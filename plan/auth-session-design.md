## 数据与权限边界

- 附加表脚本位于 `docs/mysql-auth-migration.sql`，已在用户授权的独立 MySQL 8 测试库完成基础验收；不由应用自动执行。连接时显式选择已确认的目标库，脚本不包含 `USE`、凭据、用户数据、授权或修改旧表的语句。
- 新库先执行现有初始化脚本，再执行附加表脚本；存量库只执行经过审核的附加表脚本。`IF NOT EXISTS` 不负责修复同名但结构不同的表，部署前必须核对实际结构。
- `user_id` 暂不建立指向存量用户表的外键，避免假设其字符集与排序规则；角色授予和会话创建必须检查用户存在。刷新凭据到新建会话表的关联由外键约束。
- 会话 ID 使用 32 字节安全随机值的小写十六进制字符串；摘要列为 32 字节二进制。时间列一律按 UTC 读写，不使用机器本地时区推断。
- 新增 `tb_user_role`，与 `tb_user` 分离，避免修改存量用户表；无角色记录的用户默认为普通用户。
- 初期只识别 `ADMIN`：仅管理员可新增、编辑、删除标签；文章、评论继续要求作者本人，不增加管理员代操作权限。
- 不开放客户端设置角色的接口，不根据手机号、登录先后或用户 ID 猜测管理员。
- 初始管理员由运维在确认目标环境、账号和备份后显式授权；应用和初始化脚本不自动授权。
- 三个服务在受保护请求中读取数据库会话状态与当前角色；撤销或降权在提交后的新鉴权请求生效，不承诺取消已通过鉴权的在途请求。
- 数据库不可用时鉴权失败关闭，返回脱敏的服务不可用错误，不回退到仅验签。

## 会话与令牌

- access token 默认 30 分钟，新增不可猜测的会话 ID claim；仅验签不足以视为已认证。
- refresh token 为密码学安全随机不透明凭据，只通过 HTTPS 请求体交换；数据库仅存 SHA-256 摘要，不存原文。
- 每次登录创建独立会话；默认绝对会话有效期 7 天，刷新不延长绝对有效期。
- 刷新使用事务和会话行锁串行处理，同一 refresh token 只能成功一次。
- 保留已消费 refresh token 摘要至会话过期，用于识别重放；旧 token 重放撤销对应整个会话，不撤销用户其他会话。
- 随机伪造 token 不触发任意用户或会话撤销；只对数据库中确实存在且已消费的摘要识别重放。
- 并发刷新中的第二个请求按重放处理，会撤销该会话；前端必须单飞刷新，跨标签页协调，网络结果不确定时要求重登，不自动重试旧 token。
- 退出只撤销当前会话及其刷新能力；其他设备会话不受影响。接口必须能够使用仍有效的 refresh token 撤销会话，避免 access token 已过期无法退出。
- 服务端持久化会话，重启后继续生效；数据库不可用时不能声称已完成退出。
- 存量无会话 ID 的 JWT 在新认证体系启用后拒绝，要求重新登录；该切换属于破坏性协议变更。

## WebSocket

- 握手复用 REST 的会话校验；撤销会话不能建立新连接。
- 已连接会话需在入站消息和出站投递前检查有效性，失效后关闭；不能只实现握手校验却宣称退出后 IM 权限立即失效。
- 定期清理过期连接，明确心跳/清理间隔。多实例下不能仅靠当前进程的退出事件广播撤销。

## AUTH-09A 核心进展

- 新增 JPA `AuthSession` / `AuthRefreshToken` 与 Repository，映射既有附加表；`AuthSessionService` 提供创建、轮换和会话撤销的内部方法，当前没有 Controller 或登录调用它。
- 刷新凭据使用 32 字节安全随机值，数据库只存 SHA-256；会话 ID 独立生成，时间显式使用 UTC 并截断至微秒，创建后绝对有效期固定 7 天。
- 先以摘要查询会话 ID，再锁会话行、锁凭据行；后者使用锁定读取，避免 MySQL 可重复读快照导致旧消费状态复用。所有轮换/撤销沿同一会话锁顺序串行。
- 重放或用户已删除时返回拒绝结果并提交撤销，而非抛出导致事务回滚的业务异常；新凭据持久化失败则回滚消费状态。事务超时 15 秒并配置锁等待提示，实际 MySQL 超时执行语义待验收。
- 内部撤销方法接受已知会话任一刷新凭据（包含轮换后已消费的摘要），保持幂等且只影响该会话；未知凭据不撤销任何会话。这不意味着现有 access token 已支持退出。
- 9 项 H2 JPA 独立事务测试覆盖摘要、固定期限、过期/伪造拒绝、孤立用户、重放撤销的提交、轮换失败回滚、并发刷新及刷新/退出竞争。核心已提交推送为 `1375dd4`；真实 MySQL 服务级验收见下一节。
- 后续接入必须确保 JWT 签发失败与会话写入具有正确事务边界，且所有 REST/IM 入口都检查持久化会话；届时统一发布接口变更。当前不增加 API revision，不对外提供刷新/退出接口。

## AUTH-10 限流与有界清理

- AUTH-09 随 `f983d22` 已推送；AUTH-10 的 revision 8 / 6.0.0 已发布，revision 9 / 6.0.1 评论点赞一致性兼容修复已随 `8f37bbd` 提交发布。
- 认证限流采用 Redis Lua 单键原子固定窗口：60 秒内登录 IP 20、登录账号 10、刷新 IP 60、退出 IP 30，成功/失败都占额。IP 先于 JWT/JSON，账号先于密码查询；拒绝不延长窗口。跨实例需共享 Redis、配置和密钥，不使用进程内计数降级。
- 使用 HMAC-SHA256 键，账号规范化后计数，不存原始 IP/手机号/凭据；超限 429、Redis 故障 503，业务码沿用 20001，返回 no-store 和 CORS 可读 Retry-After。应用不信任客户端转发头；代理真实来源、容量、全局限流及告警需部署层验收。
- 清理默认关闭，以数据库 UTC 和 `expires_at + retention` 判定资格，默认额外保留 24 小时。提前撤销不缩短保留期，确保会话有效期内全部重放摘要存在。
- 每轮最多 100 个候选，每会话独立短事务先锁会话并复核到期，最多删除 100 条摘要，剩余摘要下一轮继续，全部删除后才删会话；与刷新/退出沿相同锁顺序。默认每轮最多删 10000 摘要和 100 会话，多实例额度不合并。
- 会话事务失败回滚，停止本轮并记录固定脱敏警告，后续轮次重试；数据库不可用不作本地时间回退。无新表/DDL，不自动启动删除。开启需要独立授权、保留策略、备份和数据库 DELETE 权限。
- H2 事务测试覆盖批次、边界、活跃/撤销会话保护、摘要保留后仍能重放撤销、失败回滚、重复与并发清理；MVC 和模拟 Redis 覆盖 429/503、执行顺序、密钥/维度及故障关闭。真实 Redis 测试仅显式本机端口启用，默认回归不访问外部存储。
- 本轮没有真实 Redis Lua 或 MySQL 清理验收，不等同于生产容量、锁超时、代理来源或多实例网络验证。参数、验收入口和回退说明见 `docs/admin-operations.md`。
